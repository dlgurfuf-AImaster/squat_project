
# SquatMate 🏋️

**실시간 센서 데이터와 AI 코칭을 활용한 스마트 스쿼트 운동 관리 서비스**

SquatMate는 신체에 부착한 센서를 통해 스쿼트 동작을 측정하고, 운동 기록과 자세 오류를 분석하여 AI 기반 코칭을 제공하는 개인 프로젝트입니다.

Flutter 기반 모바일 애플리케이션과 Spring Boot 서버, Arduino 및 MPU6050 센서를 연동하여 운동 데이터 수집부터 기록 관리, AI 피드백 제공까지의 과정을 구현했습니다.

## 📌 Project Overview

- **개발 기간:** 2026.06 ~ 2026.10
- **프로젝트 유형:** 개인 프로젝트

- **주요 목표:** 센서 기반 스쿼트 동작 분석과 AI 맞춤형 운동 피드백 제공

## ⚙️ Squat Analysis Logic

스쿼트 동작은 허리 각도, 허벅지 각도, 수행 시간을 기준으로 판정합니다.

| 판정 항목 | 정상 조건 | 오류 조건 |
|---|---|---|
| 허리 각도 | 40° 이하 | 40° 초과 |
| 허벅지 각도 | 85° 이상 | 85° 미만 |
| 수행 시간 | 3초 이상 | 3초 미만 |

각 조건을 독립적으로 검사하며, 한 번의 스쿼트에서 여러 자세 오류가 동시에 발생할 수 있습니다.

모든 조건을 통과한 경우 정상 수행으로 집계하고, 오류가 발생한 항목은 유형별로 기록합니다.

## 🧠 Technical Decisions

### 1. 앱 중심의 실시간 스쿼트 분석

블루투스로 수신하는 센서 데이터를 Flutter 앱에서 처리하도록 설계했습니다. 각도 계산과 스쿼트 판정은 비교적 단순한 연산이며 실시간 응답이 중요하기 때문에, 서버 통신에 따른 지연과 불필요한 서버 연산을 줄이고자 했습니다.

또한 판정 로직을 앱에 배치해 향후 서버 연결이 불안정한 환경에서도 운동 측정을 수행할 수 있도록 확장 가능성을 고려했습니다.

### 2. 로컬 기록과 서버 기록의 분리

운동 기록을 SQLite에 먼저 저장하고, 사용자가 선택한 기록을 HTTP 통신으로 서버에 전송하도록 구현했습니다. 이를 통해 로컬 운동 기록 관리와 서버 기반 기록 관리의 역할을 분리하고, 서버 전송 여부를 개별 기록 단위로 관리할 수 있도록 했습니다.

### 3. 단일 AI 코칭 결과 캐싱

Gemini API의 호출 제한과 토큰 사용량을 고려해 단일 운동 기록의 코칭 결과를 서버 DB에 함께 저장하도록 구현했습니다. 코칭 요청 시 기존 결과가 있으면 재사용하고, 결과가 없을 때만 Gemini API를 호출합니다.

이를 통해 중복 API 호출을 줄이고 동일한 운동 기록에 대해 일관된 코칭 결과를 제공하도록 설계했습니다.

종합 코칭은 사용자가 선택한 기록들을 집계해 요청 시 생성하며, 현재는 생성된 종합 코칭 결과를 DB에 별도로 저장하지 않습니다.

### 4. 로우패스 필터를 활용한 센서 노이즈 완화

SquatMate는 센서에서 수신한 가속도 벡터를 이용해
허리와 허벅지의 상대 각도를 계산하고, 해당 각도를 기반으로
스쿼트 횟수와 자세 오류를 판정합니다.

따라서 순간적인 센서 노이즈는 단순한 표시 문제를 넘어
동작 시작·종료 감지와 최대 운동 깊이 판정에도 영향을 줄 수
있었습니다. 특히 실시간 각도 UI의 값이 불안정하게 변하고,
정지 상태에서도 잘못된 판정이 발생하는 문제가 있었습니다.

이를 완화하기 위해 이전 필터링 값과 현재 원본 값을 결합하는
1차 저역통과 필터를 적용했습니다. 현재 필터 계수는 0.15이며,
이전 필터링 값에 85%, 현재 원본 값에 15%의 가중치를 적용합니다.

이 방식은 순간적인 노이즈의 영향을 줄이고 각도 표시와
판정 입력값을 안정화하는 데 목적이 있습니다. 반면 실제 각도
변화도 지연되어 반영될 수 있으므로, 빠른 동작에서는 최대
각도를 충분히 반영하지 못할 가능성이 있습니다.

이에 운동 수행 시간이 3초 미만인 경우 빠른 수행 오류로
분류하도록 하여, 센서 데이터 안정화와 통제된 운동 속도 유도를
함께 고려했습니다.

## 🧪 Testing & Validation

### 1. 실제 센서 기반 동작 테스트

허벅지와 허리 위치에 센서를 배치하고, 실제 스쿼트 동작을
수행하며 실시간 각도 UI와 판정 결과를 확인했습니다.

스쿼트 관련 자료를 참고하고 직접 동작을 수행하며 허리 각도
40°, 최대 허벅지 각도 85°를 초기 판정 기준으로 설정했습니다.

다만 신체 비율과 유연성, 개인별 운동 경험에 따라 동일한
동작에서도 측정 각도에 차이가 발생할 수 있음을 확인했습니다.
따라서 해당 기준은 모든 사람의 스쿼트를 절대적으로 정의하는
값이 아니라, 초보자가 기본적인 동작 범위를 인식하도록 돕는
초기 판정 기준으로 설정했습니다.

### 2. 로우패스 필터 적용 검증

초기 구현에서는 필터 없이 센서 각도를 이용해 스쿼트 동작을
판정했습니다. 그러나 정지 상태에서도 각도 값이 흔들리면서
스쿼트 깊이를 잘못 판정하거나 동작을 안정적으로 인식하지
못하는 문제가 발생했습니다.

로우패스 필터를 적용한 후 직접 테스트한 결과, 잘못된 오류
판정이 크게 줄어들었으며 의도한 동작 판정이 더 안정적으로
이루어지는 것을 확인했습니다.

### 3. 오류 판정 로직 개선

초기에는 하나의 스쿼트 동작에서 여러 자세 오류를 판정하는
로직이 서로 복잡하게 얽혀 있었습니다. 하강과 상승 과정을
세분화하고 각 과정에서 발생한 오류를 구분하는 방식은
구현과 유지보수가 복잡하고 예외 상황도 많았습니다.

이를 개선하기 위해 각 오류 조건을 독립적으로 검사하도록
구조를 단순화했습니다. 한 번의 스쿼트에서 허리 각도, 최대
허벅지 각도, 수행 시간을 각각 평가하여 여러 오류가 동시에
발생하더라도 유형별로 집계할 수 있도록 구성했습니다.

### 4. 기록 저장부터 AI 코칭까지 통합 테스트

운동 수행 후 기록이 로컬 SQLite 데이터베이스에 저장되는지
확인했습니다. 이후 사용자가 기록을 서버로 전송하고, 서버에
저장된 기록을 조회하며, 해당 기록에 대한 AI 코칭 결과를
받는 과정까지 확인했습니다.
